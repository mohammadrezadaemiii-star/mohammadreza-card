# فهرست کامل انتقال TankerBot V7 به نسخه وب

این سند معیار پذیرش است؛ هیچ قابلیت صرفاً به‌خاطر نمایش یک کارت یا دکمه «تکمیل‌شده» محسوب نمی‌شود. هر مورد باید به رابط وب، سرویس سمت سرور، پایگاه داده، مجوزها و آزمون مرتبط متصل شود.

## 1) ورود و هویت راننده
- [ ] ورود بدون نام کاربری/رمز عبور، مطابق تجربه نسخه ربات
- [ ] دریافت و تأیید شماره موبایل و مالکیت آن در کانال‌هایی که پشتیبانی می‌کنند
- [ ] اتصال هویت یک راننده بین پیام‌رسان‌ها با شماره تأییدشده
- [ ] جلوگیری از ثبت هویت تکراری با کد ملی/موبایل
- [ ] بازگشت به آخرین کانال فعال برای پیام‌رسانی
- [ ] حفظ مسیر مستقل «ورودی کارکنان» و ورود فعلی Supabase بدون تغییر

## 2) ثبت‌نام راننده – اطلاعات هویتی و مدارک
- [ ] نام و نام خانوادگی
- [ ] کد ملی ۱۰ رقمی با کنترل رقم صحت
- [ ] موبایل و نرمال‌سازی شماره
- [ ] نام پدر و محل سکونت
- [ ] شماره گواهینامه پایه یک و تصویر گواهینامه
- [ ] تصویر کارت ملی
- [ ] شماره کارت هوشمند راننده
- [ ] پیش‌نمایش، تأیید و امکان اصلاح اطلاعات قبل از ثبت نهایی
- [ ] اعتبارسنجی فایل تصویر واقعی JPG/PNG/WEBP و محدودیت حجم ۱۲ مگابایت
- [ ] نگهداری خصوصی و امن مدارک، ثبت لاگ دسترسی و حذف کنترل‌شده

## 3) مشخصات ناوگان و تانکر
- [ ] پلاک کشنده در سه بخش (سری ایران، دو رقم، سه رقم) و نمایش استاندارد
- [ ] کارت هوشمند ناوگان
- [ ] وضعیت محور و نوع ناوگان
- [ ] وابستگی ناوگان و نام شرکت در حالت شرکتی
- [ ] نوع دیپ‌گیری
- [ ] نوع تانکر و چندگزینه‌ای‌های مربوط
- [ ] مسیر ثابت یا متغیر؛ انتخاب مبدأ/مقصد و مبدأهای ترجیحی
- [ ] نوع بارهای قابل حمل (تمیز/کثیف) و تطبیق با فهرست محموله‌ها

## 4) اطلاعات بانکی و پروفایل
- [ ] یک یا دو کارت بانکی ۱۶ رقمی با کنترل Luhn و متفاوت بودن کارت‌ها
- [ ] مشاهده پروفایل و اطلاعات ثبت‌شده
- [ ] ویرایش مرحله‌ای اطلاعات با اعتبارسنجی مجدد
- [ ] درخواست حذف حساب و تأیید مدیر
- [ ] جستجوی راننده بر اساس نام، کد ملی، موبایل، پلاک، شناسه، شهر، تانک و سایر مشخصات

## 5) جستجو و سابقه بار برای راننده
- [ ] جستجوی بارهای متناسب با مسیر، مبدأ، مقصد و ترجیحات راننده
- [ ] نمایش جزئیات بار و شرایط حمل
- [ ] تاریخچه بارهای مرتبط با راننده
- [ ] جستجوی بازه تاریخ شمسی
- [ ] صفحه‌بندی نتایج و مشاهده جزئیات
- [ ] نمایش/دریافت راهنمای تحویل اسناد

## 6) ثبت و مدیریت اعلام بار
- [ ] نوع بار تمیز/کثیف و انتخاب محموله از کاتالوگ یا ورود نام جدید
- [ ] انتخاب یک یا چند نوع تانکر موردنیاز
- [ ] نوع محور و وابستگی ناوگان موردنیاز
- [ ] مبدأ و مقصد با پیشنهاد مکان‌های پرتکرار و مقصدهای وابسته به مبدأ
- [ ] تاریخ بارگیری شمسی و میانبر امروز/فردا
- [ ] کرایه هر تن، انعام، نحوه تسویه و شرح شرایط خاص
- [ ] نوع بارنامه (کسر از بارنامه/نقدی)، پیش‌کرایه، شماره تماس و توضیحات
- [ ] پیش‌نمایش و تأیید انتشار
- [ ] فهرست بارهای فعال، ویرایش، بستن و حذف کنترل‌شده
- [ ] فیلتر و گزارش بارها بر اساس تاریخ، مسیر، محموله و وضعیت

## 7) پنل مدیریت
- [ ] داشبورد مدیر و کنترل دسترسی سمت سرور
- [ ] مدیریت بارها: ایجاد، فهرست فعال، جستجو و گزارش بازه‌ای
- [ ] مدیریت رانندگان: فهرست، فیلتر، مشاهده پروفایل و تصاویر مدارک
- [ ] مشاهده آمار رانندگان و آمار بارها
- [ ] جستجوی پیشرفته راننده و مشاهده جزئیات
- [ ] مسدودسازی/رفع مسدودی و حذف با تأیید دو مرحله‌ای
- [ ] ارسال پیام مستقیم به راننده
- [ ] پیام همگانی با انتخاب گروه/گیرندگان و گزارش ارسال
- [ ] خروجی CSV امن با خنثی‌سازی فرمول‌های صفحه‌گسترده
- [ ] خروجی فهرست مخاطبین VCF و متن دعوت

## 8) واردکردن بارنامه‌های بیتا
- [ ] دریافت XLSX و ZIP و بررسی امن محتویات ZIP
- [ ] پیش‌نمایش پیش از ثبت و نمایش خطا/هشدار هر ردیف
- [ ] تشخیص فایل‌ها/ردیف‌های تکراری
- [ ] تبدیل تاریخ و ساعت، اعداد و مبالغ
- [ ] تطبیق نام محموله و استانداردسازی
- [ ] تطبیق راننده با کد ملی و موبایل و اتصال خودکار پروفایل
- [ ] پاک‌سازی و بازسازی آمار/پروفایل‌های وابسته
- [ ] ثبت نهایی تراکنشی فقط پس از تأیید اپراتور
- [ ] گزارش خلاصه: تعداد ورودی، ثبت‌شده، تکراری، ردشده و علت‌ها
- [ ] آزمون با چند فایل واقعی و نسخه‌های مختلف قالب بیتا

## 9) قوانین اسناد و پیگیری تحویل
- [ ] تعیین قانون اسناد برای ترکیب محموله/مبدأ/مقصد و فرستنده/گیرنده
- [ ] صف بررسی ترکیب‌هایی که قانون ندارند
- [ ] تصمیم مدیر: تعیین مدارک لازم، عدم نیاز یا بررسی سفارشی
- [ ] نمایش راهنمای تحویل اسناد به راننده
- [ ] ثبت رویدادهای تحویل/دریافت اسناد و مبلغ‌های مرتبط
- [ ] نگهداری تاریخچه تصمیم‌ها و عامل انجام‌دهنده

## 10) اعلان‌های خودکار
- [ ] فعال/غیرفعال‌سازی اعلان‌ها توسط مدیر
- [ ] فقط بارنامه‌های بعد از زمان فعال‌سازی مشمول اعلان شوند
- [ ] اتصال خودکار بارنامه به راننده با تطبیق کد ملی و موبایل
- [ ] صف ارسال، زمان‌بندی، تلاش مجدد و مدیریت پیام‌های مانده
- [ ] ارسال پیام اول و پیام‌های بعدی طبق قوانین اسناد
- [ ] جلوگیری از ارسال تکراری
- [ ] گزارش موفق/ناموفق و امکان بررسی خطا
- [ ] زمان‌بند امن و مانیتورینگ اجرای وظایف

## 11) پیام‌رسان‌ها و ارتباطات
- [ ] معماری آداپتور مستقل برای هر پیام‌رسان
- [ ] بله و تلگرام فقط پس از تنظیم توکن و webhook/polling امن
- [ ] دریافت پیام، callback، فایل و عکس
- [ ] ارسال متن، عکس و سند و مدیریت خطاهای API
- [ ] قابلیت افزودن روبیکا، ایتا، سروش، آی‌گپ و واتس‌اپ پس از دسترسی به API رسمی
- [ ] عدم قراردادن توکن‌ها و کلیدهای محرمانه در مرورگر

## 12) بانک داده مرجع و ابزارهای مشترک
- [ ] کاتالوگ محموله‌ها و گروه‌بندی تمیز/کثیف
- [ ] بانک مکان‌ها، مبدأهای پرتکرار و مقصدهای پرتکرار هر مبدأ
- [ ] نرمال‌سازی ارقام فارسی/عربی، حروف عربی/فارسی، فاصله و موبایل
- [ ] تبدیل تاریخ میلادی/شمسی و نمایش ساعت محلی ایران
- [ ] اعتبارسنجی کد ملی، کارت بانکی، پلاک و مبالغ
- [ ] صفحه‌بندی، جستجوی سریع و مدیریت وضعیت فرم‌ها

## 13) امنیت، داده و سازگاری با سایت موجود
- [ ] حفظ تمام جداول و سوابق فعلی شرکت؛ بدون حذف یا تغییر مخرب
- [ ] نگاشت سازگار به schema واقعی موجود؛ عدم اجرای migration ناسازگار
- [ ] RLS دقیق برای راننده، مدیر، حسابداری، پشتیبانی و پنل‌های منطقه‌ای
- [ ] ذخیره مدارک در Storage خصوصی با مجوز حداقلی
- [ ] ثبت audit log برای تغییرات حساس
- [ ] مدیریت secrets فقط سمت سرور
- [ ] محدودیت نرخ، کنترل نوع/حجم فایل و جلوگیری از ورودی مخرب
- [ ] نسخه پشتیبان قابل بازیابی از DB و فایل‌های Storage
- [ ] تست بازگشت به نسخه قبلی؛ عدم انتشار روی main تا تأیید

## 14) آزمون‌های پذیرش
- [ ] ثبت‌نام کامل راننده از موبایل و دسکتاپ
- [ ] ثبت‌نام ناقص، خطاهای اعتبارسنجی و ادامه فرم

- [ ] آزمون نقش‌ها و دسترسی غیرمجاز

## وضعیت فعلی
- صفحه اصلی شاخه آزمایشی به پوسته اولیه درگاه رانندگان تغییر کرده است.
- صفحه ورود قبلی کارکنان در فایل جداگانه staff.html کپی شده و پیوند آن در صفحه اصلی قرار گرفته است.
- ماژول‌های JavaScript اولیه برای نرمال‌سازی، تطبیق راننده، واردکردن بیتا، قوانین اسناد و اعلان‌ها وجود دارند؛ اما هنوز همه جریان‌های بالا به UI و دیتابیس واقعی وصل نشده‌اند.
- migration اولیه با schema زنده سازگار نیست و نباید روی production اجرا شود.
- این چک‌لیست عمداً معیار پذیرش است؛ موارد انجام‌نشده تا زمان پیاده‌سازی و تست، انجام‌شده اعلام نمی‌شوند.
